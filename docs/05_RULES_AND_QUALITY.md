# 05: Rules, Quality, Testing and Submission

## Code quality
- TypeScript with strict types. No `any` unless unavoidable and commented.
- Small files, small functions, clear names. Screens only show UI and call hooks; logic lives in `logic/`, storage in `data/`, audio and services in `services/`.
- No dead code, no commented-out blocks, no stray `console.log`.
- Handle errors gracefully (missing permission, audio failed to load). The app must not crash.
- Constants in one place (durations, pattern data, sound catalog).

## Git
- `git init` at the start. Proper `.gitignore` (node_modules, build outputs, local.properties, .idea, keystores that are not the debug one).
- Small, regular commits with clear messages, for example `feat: add box breathing pattern`, `fix: stop double counting sessions`, `docs: update README`.
- Do not push to any remote unless Hashim gives the remote URL and says yes.

## Audio and asset rules
- Only royalty-free, CC0, or self-made audio. Good places to look: Freesound (filter by Creative Commons 0), OpenGameArt (CC0), Pixabay (royalty-free licence). Prefer CC0. Check the licence on every file. Do not use anything marked NonCommercial or that requires attribution unless attribution is added in the README and About text.
- A neutral white noise or a simple soft bell can be **generated by us** (for example with ffmpeg or a small script). That counts as created by us.
- If you cannot download files yourself, tell Hashim exactly which sounds are needed (rain, ocean waves, forest, white noise, a soft bell) and where to put them (`assets/audio/ambient`, `assets/audio/bells`). Do not leave fake or empty files and do not call that milestone done.
- Format and size: OGG (or AAC), loops of about 30 to 90 seconds, edited so the end joins the start smoothly. Keep the total audio size reasonable (aim for under about 15 MB overall).
- Record every file in `assets/audio/SOURCES.md`: file name, title, author, URL, licence, any edits made.
- Do not use any name, logo, icon, screenshot, text, artwork or audio from the "Calm" app.
- Placeholder app name `Q9 Relax` and a simple placeholder icon (plain shape or letter on a soft background).

## Testing checklist (run in Milestone 6)
Run on **one real Android phone and one emulator**, portrait, and in **dark mode** (also check light mode).

Home and navigation
- [ ] App opens without a crash; greeting is correct; three cards work; back button works
Breathing
- [ ] Box and 4-7-8 each run for 1 minute with cue and circle always in sync
- [ ] One 5-minute run has no visible drift
- [ ] Pause, resume, stop work; stopped session is not counted; completed session is counted
Meditation
- [ ] 5-minute timer with screen off finishes on time with the end bell
- [ ] Pause/resume keeps correct remaining time; stop is not counted
- [ ] Bell setting off means silence at start and end
Sounds
- [ ] All four or more sounds play, loop without an audible gap, and switch cleanly
- [ ] Volume slider works
- [ ] Screen off and app in background: sound continues; media notification shows controls; stop from the notification works
- [ ] Phone call or other app audio pauses sound correctly
Sleep timer
- [ ] 15-minute sleep timer stops the sound with the screen off (checked at least once on the real device)
Progress and settings
- [ ] Force-close and reopen: progress, theme and bell setting are kept
Offline and release
- [ ] Final APK installs on the real phone, airplane mode on, Metro closed: everything works
- [ ] No red/yellow error screens; no crash

Write the results (pass/fail, device model, Android version) in `PROGRESS.md`.

## README.md must contain
1. App name (placeholder) and a one-paragraph description
2. **How to build** (prerequisites, install, run on emulator, build the shareable APK; commands for Windows)
3. **What is done** (MVP features list)
4. **What is pending / known issues** (honest list)
5. **Sources and licences** of all audio and assets (link to `assets/audio/SOURCES.md` and list them)
6. Notes for the Technical Lead: libraries used and why, background audio and timer approach
7. Tested on: devices, Android versions, emulator

## PROGRESS.md structure

```
# Progress

## In progress
## Pending
## Known issues

## Questions for Technical Lead
```

## Final reminder to the agent
Be honest. If something does not work yet, say so, write it in the README under "pending", and tell Hashim. A smaller app that works smoothly is better than a bigger one that is half finished.
